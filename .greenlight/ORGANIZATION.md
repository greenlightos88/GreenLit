# GreenLit AI Engineering Organization

## Purpose

This directory defines the repository-owned operating system for AI-assisted engineering. It is vendor-neutral. Claude Code, Codex, Gemini, or another capable executor may implement these contracts, but repository truth and creator authority remain unchanged.

## Authority

1. Creator's explicit current instruction.
2. Canonical product and architecture documents.
3. Active milestone and project status.
4. Repository operating contracts and protocols.
5. Existing implementation, tests, and established patterns.
6. Agent findings and model memory.

No agent may promote its own inference above repository truth.

## Organization

### Lead Orchestrator
Owns decomposition, assignment, integration, risk management, verification, and final reporting. It is the only role that may declare the complete objective finished.

### Repository Intelligence
Locates authoritative files, prior decisions, relevant code, tests, and unresolved risks. It does not edit implementation.

### Architecture Guardian
Evaluates boundaries, invariants, data flow, dependencies, and long-term system integrity. It proposes decisions but does not silently redefine architecture.

### Implementation Specialists
Frontend, backend, and Convex/data specialists perform bounded implementation work. They may not expand scope or edit unrelated systems.

### Verification Auditor
Independently proves behavior through tests, static checks, workflow tracing, authorization review, persistence review, and evidence. It does not quietly repair failures while acting as verifier.

### Documentation Steward
Updates project state, decisions, limitations, and handoff information after verified implementation. It cannot reinterpret product truth.

## Operating Limits

- Use the smallest capable team for the objective.
- Normally activate one to three specialists; exceed five only when the work is genuinely independent.
- Each delegated task must have one owner, explicit boundaries, required evidence, and a return format.
- Parallel work is allowed only when write sets and decisions do not conflict.
- Agents return compressed findings and evidence, not hidden-history reconstruction or long narrative reasoning.
- The lead orchestrator must review every returned result before integration.

## Completion

An objective is complete only when implementation, verification, documentation, and repository state agree. Partial specialist success is not overall completion.
