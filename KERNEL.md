# GreenLight Kernel

The GreenLight Kernel is a set of architectural responsibilities. It is not a mandate to create duplicate runtime infrastructure or rename working modules for conceptual neatness.

## Creative Kernel

Responsibilities:

- ingest creative material;
- preserve Fragments and source versions;
- maintain provenance;
- connect related material;
- expose context for interpretation;
- preserve original creator expression before analysis.

## Canon Kernel

Responsibilities:

- manage Candidate lifecycle;
- record creator review decisions;
- approve, edit, reject, or defer proposals;
- version durable project objects;
- create immutable Canon snapshots;
- compute structural diffs;
- preserve authorship and approval history.

## Compiler Kernel

Responsibilities:

- consume immutable Canon snapshots;
- build professional artifacts through typed builders;
- preserve field-level source references;
- surface missing information as structured warnings;
- distinguish generated connective prose from approved facts;
- never invent facts to create professional polish.

## Production Kernel

Responsibilities:

- extract production implications;
- route human confirmation;
- support breakdowns, continuity, scheduling, budgeting, departments, safety, access, cultural review, and production risk;
- avoid false certification or automated authority claims.

## Delivery Kernel

Responsibilities:

- freeze deliverable versions;
- manage review state;
- preserve historical packages;
- route external feedback back through creator decisions;
- prevent later Canon changes from mutating prior deliveries.

## Mapping Rule

These domains map onto existing GreenLight modules. New infrastructure should be introduced only when a concrete capability or invariant requires it.
